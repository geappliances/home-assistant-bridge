# GE Appliances Bridge for ESPHome

ESPHome external component bridging GE Appliances (GEA2/GEA3 serial protocols) to Home Assistant via MQTT.

| | |
|---|---|
| **Hardware** | FirstBuild Home Assistant Adapter (SeeedStudio Xiao ESP32-C3) |
| **Protocol** | GEA2 (19200 baud) / GEA3 (230400 baud) |
| **Transport** | MQTT with Home Assistant Auto-Discovery |
| **Platform** | ESP32-C3 / ESP32-C6, ESP-IDF framework |
| **License** | BSD 3-Clause |

---

## Prerequisites

The following must be configured on your Home Assistant installation before setting up the bridge:

1. **[ESPHome Add-on](https://esphome.io/guides/getting_started_hassio/)** — for building and flashing firmware.
2. **[MQTT Broker](https://www.home-assistant.io/integrations/mqtt/)** — for communication between the bridge and Home Assistant.
3. **FirstBuild Home Assistant Adapter** — available from [FirstBuild](https://firstbuild.com/inventions/home-assistant-adapter/).
4. **GE Appliance** with a GEA2 or GEA3 serial port.

---

## Setup

### 1. Configure Secrets

In the ESPHome dashboard, click the three-dot menu in the upper right and select **Secrets**. Add the following entries with values matching your environment:

```yaml
wifi_ssid: "YourNetworkName"
wifi_password: "YourWiFiPassword"
mqtt_broker: "192.168.1.100"
mqtt_username: "your_mqtt_user"
mqtt_password: "your_mqtt_password"
```

### 2. Create a New Device

In the ESPHome dashboard, click **Add Device** in the lower right, then select **Advanced Options** → **Empty Configuration**. Set a unique device name in the dialog box. The initial configuration generated by ESPHome Device Builder will look like this:

```yaml
esphome:
  name: yourDeviceName
  friendly_name: yourDeviceName

# Replace this with your actual platform if you aren't using ESP32.
esp32:
  board: esp32dev

logger:

api:
  encryption:
    key: "••••••••••••••••••••••••••••••••••••••••••••"

ota:
  - platform: esphome

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:
    ssid: test-device Fallback Hotspot
    password: "••••••••••••"

captive_portal:
```

### 3. Update the ESP32 Section
Replace the esp32 section with the following:

```yaml
esp32:
  board: seeed_xiao_esp32c3
  framework:
    type: esp-idf

```

### 4. Paste the following at the end of the configuration page
```yaml
external_components:
  - source: github://joshualongenecker/home-assistant-bridge-esphome@develop
    components: [ geappliances_bridge ]

mqtt:
  broker: !secret mqtt_broker
  username: !secret mqtt_username
  password: !secret mqtt_password
  port: 1883
  discovery: true
  discovery_prefix: homeassistant

uart:
  - id: gea3_uart
    tx_pin: GPIO21  # D6 on Xiao ESP32-C3
    rx_pin: GPIO20  # D7 on Xiao ESP32-C3
    baud_rate: 230400

  - id: gea2_uart
    tx_pin: GPIO9   # D9 on Xiao ESP32-C3
    rx_pin: GPIO10  # D10 on Xiao ESP32-C3
    baud_rate: 19200
    rx_full_threshold: 1
    rx_timeout: 1

geappliances_bridge:
  gea3_uart_id: gea3_uart
  gea2_uart_id: gea2_uart
```

### 5. Build and Flash

1. Click **Install** in the lower right and select **Plug into this computer** to compile the firmware.
2. Once compilation finishes, go to [ESPHome Web](https://web.esphome.io) in a supported browser (Chrome, Edge, or Chromium).
3. Connect the adapter to your computer via USB, then flash the compiled firmware.
4. Disconnect the adapter from your computer and connect it to your GE Appliance's serial port using a standard Ethernet cable (RJ45).
5. The adapter should appear as **Online** in your ESPHome dashboard within a minute.

**Startup phases shown above:**

| Phase | What happens |
|---|---|
| **Autodiscovery** | Broadcasts on GEA bus, finds appliance at address `0xC0` |
| **Identity** | Reads appliance type, model number, serial number |
| **Feature bits** | Probes ERDs `0x0092`–`0x010D` to determine supported features |
| **Bridge init** | Subscribes to or polls ERDs based on mode |
| **Steady state** | Bridge is running and reporting appliance data |
| **Discovery Cleanup** | Removes previous/old MQTT Discovery topics (After OTA Only) |
| **Discovery Publish** | Publishes new MQTT Discovery topics based on the latest appliance definitions (After OTA Only) |


MQTT discovery topics are published by the bridge and retained on the MQTT broker. On normal boots, discovery is skipped — the broker retains the topics from the previous session. Discovery runs in two scenarios:

- **After OTA reboot:** The bridge detects an OTA reboot, cleans old discovery topics, publishes fresh ones, and reboots to defragment the heap.
- **Discovery Refresh button:** Manually triggers cleanup of stale topics, republishes fresh discovery, and reboots.

### 6. View your GE Appliances device in Home Assistant

Navigate to Settings -> Devices & Services -> Devices, and then search for your autogenerated deviceid (for example, Dishwasher_PDT715SBN8TS_AB123456C). You should see your device preconfigured with sensors and controls! If you find anything unexpected (wrong units, scaling factor, unknown data, unresponsive, etc) please file an [Issue Ticket](https://github.com/joshualongenecker/home-assistant-bridge-esphome/issues/new) with what you've found!
